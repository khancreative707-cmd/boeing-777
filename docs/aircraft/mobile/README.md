# Mobile aircraft interface

Phones retain independent left/right engine controls, throttle percentages, Sectional and a More controls disclosure in a compact dock. Secondary controls open in an overlay sheet, keeping the aircraft viewport from shrinking. The mechanisms panel scrolls independently and has an explicit Done action. Desktop keeps the complete operating bar.

The camera toolbar is one horizontally scrollable row with larger touch targets. The portrait camera leaves room for both wingtips, while focused parts reserve the actual space between the toolbar and instruments. The renderer continues to use the full viewport. Narrow screens use larger assembly/inspector drawers, readable search inputs and 44 px primary controls. Drawers expose dialog semantics, contain keyboard focus, make the background inert, close with Escape and restore focus to their opener. Opening a drawer closes the control sheet. Device safe areas and touch scrolling are respected. Short landscape pages scroll to controls instead of clipping them.

Validation: the full 54-test model suite and production build passed. `npm run test:mobile` exercises actual touch controls at 320×640, 390×844 and 430×932; tablet at 768×1024; landscape at 844×390; and desktop at 1568×1003. Checks cover overflow, control height, single-row toolbar, disclosures, flap/speed controls, modal search/selection, focus/Escape restoration, projected focused-part bounds, actual touch-drag camera orbit, tablet inspector and landscape access. Browser plugin unavailable: Playwright/Chromium was used. Cloud software rendering does not establish real-device FPS or Safari behavior.

See [verification.json](verification.json) and actual screenshots in this directory. The earlier complete engine/aircraft browser reports remain separate from this focused mobile pass.

Its [follow-up report](tablet-verification.json) is also embedded in the main report. The short landscape workspace is bounded at 380 px and its screenshot captures the complete scrollable page. `test:mobile` runs both browser scripts sequentially.
